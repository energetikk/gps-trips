# GPS Поездки

Простое Android-приложение для магнитолы: читает лог внешнего GPS-приёмника
(u-blox M9N через USB), собирает из него поездки и показывает статистику —
на экране магнитолы и в Telegram.

APK: `dist/gps-poezdki-1.0-debug.apk`

## Что умеет

- разбирает текстовые NMEA-логи (`$xxRMC`, `$xxGGA`, `$PUBX,00` от u-blox) и GPX;
- режет трек на поездки, считает расстояние, длительность, время в движении,
  среднюю и максимальную скорость;
- главный экран: сводка за сегодня / 7 / 30 дней и список поездок по дням;
- экран поездки: цифры, профиль скорости, трек на карте OSM (● старт, ● финиш);
- отправка сводки или отдельной поездки в Telegram-бот (в личку или в приватную группу).

## Установка на магнитолу

1. Скопируйте `dist/gps-poezdki-1.0-debug.apk` на флешку и откройте её
   файловым менеджером на магнитоле (или передайте файл любым удобным способом).
2. Разрешите установку из неизвестных источников, когда система спросит.
3. Либо по adb: `adb install -r dist/gps-poezdki-1.0-debug.apk`

Приложение не требует root и не лезет в USB-порт: оно работает с файлом,
который уже пишет приложение GPS-модуля.

## Первый запуск

1. **Настройки → Разрешить доступ к файлам** — на Android 11+ нужно дать
   «Доступ ко всем файлам», иначе папку с логами не прочитать.
2. Укажите папку с логами:
   - «Выбрать папку» — системный диалог (на части магнитол его нет);
   - «Путь вручную» — например `/storage/emulated/0/GPS`.
3. «Обновить» — приложение прочитает все `.nmea`, `.txt`, `.log`, `.gpx`
   из папки и вложенных папок (до 3 уровней).

Проверить работу без реальных логов: скопируйте на магнитолу файл
`sample/demo-20251112.nmea` в любую папку и укажите её — получится две поездки.

## Telegram

1. В Telegram у **@BotFather** выполните `/newbot`, задайте имя — получите токен
   вида `1234567890:AAH...`.
2. Создайте приватную группу, добавьте туда бота (бот должен быть участником,
   лучше — с правом отправки сообщений).
3. Узнайте `chat_id`:
   - напишите любое сообщение в группу, откройте в браузере
     `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найдите
     `"chat":{"id":-1001234567890,...}` — это и есть `chat_id` (у групп он
     отрицательный);
   - для лички — свой числовой id (например через бота `@userinfobot`).
4. В приложении: **Настройки → Telegram** → вставьте токен и `chat_id` →
   «Сохранить» → «Отправить сводку».

Сервер не нужен: приложение само вызывает Bot API, как только появляется интернет.

## Сборка из исходников

Нужен JDK 17 и Android SDK с платформой 34.

```powershell
# локально
$env:JAVA_HOME = "C:\path\to\jdk17"
.\gradlew.bat assembleDebug testDebugUnitTest
```

- **Android Studio**: открыть папку проекта и нажать Run.
- **GitHub Actions**: workflow `.github/workflows/build.yml` собирает APK и
  тесты на каждый push, готовый файл — в артефактах сборки.

## Как считаются поездки

Логика намеренно простая и проверяемая (тесты в `app/src/test`):

- точки сортируются по времени; дубли (две строки в одну секунду), нулевые
  координаты и «телепорты» (сотни метров за пару секунд) отбрасываются;
- пауза больше **5 минут** закрывает поездку, следующая точка начинает новую;
- отрезок короче **300 м** поездкой не считается;
- средняя скорость = расстояние / время, когда скорость была выше 3 км/ч;
- максимальная скорость — 98-й перцентиль, чтобы одиночный выброс приёмника
  не портил цифру;
- если в GPX вместо времени стоит 1970 год (так делают некоторые экспортёры),
  поездка помечается как «время недостоверно» и длительность не показывается.

## Ограничения текущей версии

- APK отладочный (`debug`), подписан debug-ключом — для личного использования
  этого достаточно, для публикации нужен свой ключ.
- Карта берёт тайлы OpenStreetMap из интернета; без сети остаётся тёмный фон с
  линией трека. Кэш тайлов только в памяти, после перезапуска качаются заново.
- Сборка и тесты ядра проверены локально; на самой магнитоле приложение
  ещё не запускалось — первую установку стоит делать с запасом времени.
- Бинарные логи (`ubx`) и CSV не поддерживаются.
